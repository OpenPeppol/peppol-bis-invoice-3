[horizontal]

== Enveloping of BIS message in Peppol Business Message Envelope (SBDH)
* When a BIS message is enveloped, the value of the SBDH element *Sender/Identifier* SHALL match the *Party/EndpointID* element value of the sender party, including the value of its *schemeID* attribute.

* When a BIS message is enveloped, the value of the SBDH element *Receiver/Identifier* SHALL match the *Party/EndpointID* element value of the receiver party, including the value of its *schemeID* attribute.


Example:
[attributes]
====
    BIS message: 
        <cbc:EndpointID schemeID="0088">7315458756324</cbc:EndpointID>

    SBDH envelope: 
        <Identifier Authority="iso6523-actorid-upis">0088:7315458756324</Identifier>
====

To support implementers, a Schematron file is provided for automated validation of the enveloping rules described above. Use of this Schematron is optional, however conformance to the rules themselves is mandatory.

See Policy for use of Identifiers for more information on how to represent identifiers in envelope and messages.
Policy for use of Identifiers: https://docs.peppol.eu/poacc/concept/identifier/ Policy 2 Identifier value casing

Remark:
Although an underlying identifier (such as a Chamber of Commerce or VAT number) could theoretically contain uppercase letters, Peppol mandates that software and access points must be case-insensitive during lookups (SMP lookups) and routing, in order to prevent delivery errors.

That means that a value in the payload still can adhere to a validation rule that triggers when its value is not using the correct format.
