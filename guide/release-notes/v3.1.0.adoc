== Changes to BIS document

* Updated the country restrictions documented for invoice type codes 384 and 389: code 384 is available for Germany and Slovakia, while code 389 is restricted to Germany.

== Changes to code lists and validation artefacts
* Codelist publication date: 2026-09-11
* Validation artefacts UBL and CII updated to version 1.3.17, publication date 2026-10-09.
* BR-CO-09 is unchanged from CEN 1.3.17. The country list does not accept the Greek VAT prefix EL. A comment above the rule records the prepared change, adding EL after EH. That change is not in this release. Apply it when the Greek Peppol Authority submits an RFC. Until then, GR-R-003 still requires EL for a Greek supplier VAT identifier.
* Local corrections on top of the CEN publication:
** CII rule ids BR-IG and BR-IP follow the UBL meaning. BR-IG is IGIC, category L. BR-IP is IPSI, category M.
** CII-SR-035 and CII-SR-221 apply to the invoice line again. CII-SR-039 to CII-SR-044 share the line-document context with CII-SR-036 to CII-SR-038, so those warnings fire.
** UBL-SR-25 says the deliver-to party name occurs exactly once when a deliver-to party is present. UBL-SR-59 says the payee financial account contains exactly one payment account identifier (BT-84).

==  Changes to Country-Specific Rules
* Rule DE-R-017 stays a warning. The text now says SHOULD instead of "should". Invoice type code 389 was already in the allowed list. UBL only.
* Rule DE-R-T02 becomes fatal. It was introduced as a warning in May 2026. The text says MUST. Leading and trailing whitespace in the URL is ignored. UBL only.
* Removed rule and sample check GR-R-001-5 for Greece (GR) https://openpeppol.atlassian.net/browse/RFC-563[RFC-563], UBL only
* Rules GR-R-001-1, GR-R-008-2 and GR-R-008-3 stay fatal. The text now says MUST instead of SHOULD. The checks are unchanged. UBL only.
* Rule GR-S-011 stays a warning. The text now says SHOULD instead of "must". UBL only.
* Added warning rule SK-R-001 requiring a preceding invoice reference (BG-3) for Slovak domestic invoices with invoice type code 384, UBL only
* Added rules SK-R-002, SK-R-003, SK-R-004, SK-R-005, SK-R-006, SK-R-007 for Slovakia (SK) https://openpeppol.atlassian.net/browse/RFC-574[RFC-574], UBL only
* Rules SK-R-001, SK-R-002, SK-R-003, SK-R-004, SK-R-005, SK-R-006 and SK-R-007 are new in this release and stay warnings. They become fatal in the May 2027 release.
* Changed rule SE-R-006 for Sweden (SE) so that it only applies to domestic transactions: in addition to the existing Swedish Seller condition, the Buyer country code (BT-55) must be SE. Swedish sellers invoicing buyers in other countries are no longer restricted to the VAT rates 6, 12 and 25. UBL and CII. The CII rule still checks every VAT category. UBL checks category S only. A comment above the CII rule records the prepared change. Apply that change when the Swedish Peppol Authority submits an RFC. PEPPOL-25729 does not cover this difference.
* CII tax-scheme selectors use schemeID VA. Rules for Sweden, Norway and Italy therefore apply to a conformant CII invoice. UBL and CII.
* DK-R-003 is fatal in CII. DK-R-017 is present in CII and requires scheme 0184 on the buyer legal identifier for a Danish domestic invoice.
* Rules SE-R-007, SE-R-008, SE-R-009 and SE-R-010 stay warnings. The text now says SHOULD instead of "must". UBL and CII.


== Changes to PEPPOL-COMMON rules

* Changed rule PEPPOL-COMMON-R040 to ONLY allow GLN13 values with schemeID 0088. In CII the check covers the electronic address, the party identifier and the legal identifier. It does not cover the deliver-to location (BT-71) or the item identifier (BT-157). The same limit applies to R043 and R059. UBL and CII.
* Fixed example files that still carried a non-GLN value with scheme 0088. The values are now a 13-digit GLN.
* Rule PEPPOL-COMMON-R040 stays fatal. The text now says MUST. UBL and CII.
* Updated validation method on rule PEPPOL-COMMON-R043 (fatal) so a Belgian enterprise number (schemeID 0208) must be 10 digits starting with 0 or 1 and pass the mod-97 check. UBL and CII.
* Changed the wording of warning rules PEPPOL-COMMON-R044, PEPPOL-COMMON-R045, PEPPOL-COMMON-R046, and PEPPOL-COMMON-R047 from “must” to “SHOULD” to align the rule text with the severity. Updated other lowercase should to uppercase SHOULD. https://openpeppol.atlassian.net/browse/RFC-558[RFC-558]
* Changed rules PEPPOL-COMMON-R054, PEPPOL-COMMON-R055, PEPPOL-COMMON-R056-1, PEPPOL-COMMON-R056-2, and PEPPOL-COMMON-R057 from warning to fatal after the announced transition period. https://openpeppol.atlassian.net/browse/RFC-541[RFC-541]
* Added rule PEPPOL-COMMON-R058 (introduced as warning, will change to fatal in coming release) for validation of Luxembourg VAT numbers. The VAT number must follow the format LU followed by 8 digits, where the last 2 digits are the check digits computed as the first 6 digits modulo 89. Applies to Seller VAT identifier (BT-31), Buyer VAT identifier (BT-48), and Tax representative VAT identifier (BT-63). UBL and CII.
* Added rule PEPPOL-COMMON-R059 (introduced as warning, will change to fatal in coming release) for validation of Luxembourg Register of Legal Persons numbers (Matricule, schemeID 0240). The number must be exactly 11 digits; digits 5–6 must be a legal form type code in the range 20–99; and digit 11 must be a valid mod-11 check digit (with an alternative check digit supported for legal form type 24). Applies to the seller electronic address (BT-34), seller identifier (BT-29), seller legal registration identifier (BT-30), buyer electronic address (BT-49), buyer identifier (BT-46), and buyer legal registration identifier (BT-47). UBL and CII.
* Added rule PEPPOL-COMMON-R062 (warning) for validation of Belgian VAT numbers. The number is BE, then 0 or 1, then nine digits, and the digits pass the same modulo 97 check as the Belgian enterprise number. A lower-case prefix is checked as well. UBL and CII. The rule stays a warning and becomes fatal in the May 2027 release.

==  EN 16931 schematrons updated
* Rules PEPPOL-EN16931-CL001 and PEPPOL-EN16931-CL006 stay fatal. The text now says MUST instead of "must". CL001 applies to UBL and CII. CL006 applies to UBL only, because CII has no invoice period description code.
* Rule PEPPOL-EN16931-P0112 did not change in this release. The update was added in the 3.0.22 hotfix, link:https://openpeppol.atlassian.net/browse/RFC-607[RFC-607], and is kept here for reference because it was initially added for this version. Invoice type code 384 is allowed when both buyer and seller are German organizations or both are Slovak organizations. Invoice type codes 326 and 389 are only allowed when both buyer and seller are German organizations. UBL only.
* Added fatal inferred mandatory-cardinality rules PEPPOL-EN16931-R140 through PEPPOL-EN16931-R276, except the rules that only repeat a 1..1 constraint of the UBL 2.1 schema. Those rules can never fail on a schema-valid document and are not shipped: R140, R147, R157, R163, R171, R180, R198, R201, R209, R216, R226, R232, R236, R243, R251, R266 and R269. UBL only.
* The country variables used by P0112 take the first VAT prefix when a party has more than one VAT identifier, so the Peppol schematron still produces a report.

== Changes to SBDH envelope rules
* Rules BR-SBDH-1, BR-SBDH-2, BR-SBDH-3 and BR-SBDH-4 now compare the SBDH Sender/Receiver Identifier with the Party/EndpointID (including its schemeID) case-insensitively, in line with the Peppol policy for identifiers. Leading and trailing whitespace is trimmed from the element values (SBDH Identifier and EndpointID), not from the schemeID attribute, while whitespace inside an identifier is significant. The rules stay fatal. Applies to Invoice and CreditNote.
