== Changes to Country-Specific Rules

The countries are in alphabetical order. Within a country the rules follow the rule number.

* Germany (DE), UBL only
** Invoice type code 389 is now included in the list of allowed German invoice type codes. It was missing.
** Rule DE-R-T02 becomes fatal. It was introduced as a warning in May 2026. It checks that BT-124 "External document location" is an absolute URL with a valid scheme when both the seller and the buyer are in Germany. The six-month transition ends with this release. The text says MUST.

* Greece (GR), UBL only
** Removed rule GR-R-001-5 and its sample check. [RFC-563](https://openpeppol.atlassian.net/browse/RFC-563)
** Rules GR-R-001-1, GR-R-008-2 and GR-R-008-3 stay fatal. The text now says MUST instead of SHOULD. The checks are unchanged.
** Rule GR-S-011 stays a warning. It was changed from fatal to warning in May 2023. The text now says SHOULD instead of "must".

* Slovakia (SK), UBL only
** Added warning rule SK-R-001. A Slovak domestic invoice with invoice type code 384 must contain a preceding invoice reference (BG-3). The rule is new in this release, so it stays a warning.
** Added warning rules SK-R-002, SK-R-003, SK-R-004, SK-R-005, SK-R-006 and SK-R-007. [RFC-574](https://openpeppol.atlassian.net/browse/RFC-574) These rules are new in this release, so they stay warnings.

* Sweden (SE), UBL and CII
** Changed rule SE-R-006 so that it only applies to a domestic transaction. The buyer country code (BT-55) must be SE, in addition to the existing condition that the seller is Swedish. A Swedish seller invoicing a buyer in another country is no longer limited to the VAT rates 6, 12 and 25.
** Rules SE-R-007, SE-R-008, SE-R-009 and SE-R-010 stay warnings. The text now says SHOULD instead of "must". These are existing warnings, so they do not become fatal.

== Changes to PEPPOL-COMMON rules

The rules are listed by rule number.

* Changed rule PEPPOL-COMMON-R040, UBL and CII. A GLN-13 is only accepted with schemeID 0088. The rule stays fatal, and the text now says MUST.
** Corrected five example files that contained an invalid GLN, so they pass PEPPOL-COMMON-R040.
* Updated rule PEPPOL-COMMON-R043 (fatal). The check for a Belgian enterprise number now requires the same format as agreed for this release.
* Changed the wording of warning rules PEPPOL-COMMON-R044, PEPPOL-COMMON-R045, PEPPOL-COMMON-R046 and PEPPOL-COMMON-R047 from "must" to "SHOULD". The rules stay warnings. [RFC-558](https://openpeppol.atlassian.net/browse/RFC-558)
* Changed rules PEPPOL-COMMON-R054, PEPPOL-COMMON-R055, PEPPOL-COMMON-R056-1, PEPPOL-COMMON-R056-2 and PEPPOL-COMMON-R057 from warning to fatal. These Dutch identifier rules were introduced as warnings in May 2026. The six-month transition ends with this release. [RFC-541](https://openpeppol.atlassian.net/browse/RFC-541)
* Added rule PEPPOL-COMMON-R058 as a warning, UBL and CII. It checks a Luxembourg VAT number: LU followed by 8 digits, where the last 2 digits are the check digits of the first 6 digits modulo 89. It applies to the seller VAT identifier (BT-31), the buyer VAT identifier (BT-48) and the tax representative VAT identifier (BT-63). The rule is new in this release. It becomes fatal in the May 2027 release.
* Added rule PEPPOL-COMMON-R059 as a warning, UBL and CII. It checks a Luxembourg Register of Legal Persons number (Matricule, schemeID 0240). The number must be exactly 11 digits, digits 5–6 must be a legal form type code from 20 to 99, and digit 11 must be a valid mod-11 check digit. It applies to the seller identifier (BT-29), the seller legal registration identifier (BT-30), the buyer identifier (BT-46) and the buyer legal registration identifier (BT-47). The rule is new in this release. It becomes fatal in the May 2027 release.
* Added rule PEPPOL-COMMON-R062 as a warning. A VAT identifier that starts with BE must have the form BE, then 0 or 1, then nine digits, and the digits must pass the modulo 97 check. The rule is new in this release, so it stays a warning. It becomes fatal in the May 2027 release. The text says MUST, which is allowed for a new rule during the transition.

== Changes to code list rules

* Rules PEPPOL-EN16931-CL001 and PEPPOL-EN16931-CL006 stay fatal. The text now says MUST instead of "must". CL001 applies to UBL and CII. CL006 applies to UBL only, because CII has no invoice period description code.

== Other changes
* Updated rule PEPPOL-EN16931-P0112 for Slovakia (SK). [RFC-585](https://openpeppol.atlassian.net/browse/RFC-585) UBL only.
* Added fatal rules PEPPOL-EN16931-R140 through PEPPOL-EN16931-R276. These 137 rules require exactly one occurrence of UBL elements that the structure model declares mandatory. UBL only. The current unit test covers R257 and R258.
